# VIS07 viewer integration: prospective endpoint

The selected seed240 model, the fixed first original TRAIN class0 image, the original vector renderer and the original GPU T0–8 archive are admitted by exact hash before execution. Twenty-seven startup gates compare every complete state and logit array with `1e-4 + 1e-5*abs(reference)` and every categorical scanner decision exactly. The server then resets to T0.

The integration client tests HTTP serialization through the same nine steps and unchanged numerical limits, the actual execution-mode flag, ten original TRAIN sample resets, the depth-eight cap and clean bounded-server release. Physical NVIDIA execution and CPU/Mesa software execution are separate endpoints and receipts. Neither archive playback nor software execution substitutes for the physical live integration gate. No training, test-accuracy selection or tolerance change occurs.

Source/data hashes are frozen before either execution. Physical work uses shared GPU FIFO, available RAM at least8GiB and twoCPUthreads; software work uses the existing standard CPU laboratory with the same guard. Software execution requires an actual software renderer fingerprint and is not labelled physical GPU. All failures remain preserved. These are internal engineering checks, not independent outside replication.
