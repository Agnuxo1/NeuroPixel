# Item 9: independently checking the intermediate archive gate

The new `scripts/research_item9_gate_archive_audit.py` checks the completed Stage-B archive against Git objects already recovered by root. It uses only the standard library and read-only Git commands. It does not fetch, move refs, create a worktree, run a model, deserialize a checkpoint, inspect numerical prediction arrays, or change the frozen source. The raw archive must already be complete; this helper is not for monitoring partial results.

```sh
python scripts/research_item9_gate_archive_audit.py \
  --input /absolute/path/to/recovered/results/research/09_cloud_runs/RUN-ATTEMPT-study \
  --source-commit SOURCE_SHA \
  --archive-commit FINAL_ARCHIVE_SHA \
  --remote-head RECOVERED_RESULTS_BRANCH_HEAD_SHA \
  --output /absolute/path/outside-raw/new_gate_archive_audit.json
```

All three supplied commit IDs must be complete lowercase 40-character hexadecimal values. Root must independently identify the repository, final commit and remote branch head. The helper performs no network lookup; `--remote-head` is an externally supplied anchor, not a server response obtained by this script. The recovered checkout must have the final commit as HEAD. Missing/shallow Git history is reported as a failure; it is never repaired by an automatic fetch. The output must be new and outside the raw directory.

The helper extracts `G`, the claimed intermediate commit, from `gate_archive_receipt.json` **at the final commit F**. It checks that G is a distinct ancestor of F and F an ancestor of the supplied remote head H. It then opens G directly, verifies the complete intermediate manifest and exact regular-file inventory, and hashes the copied bytes. Its inventory must contain the ten declared seeds/families and 4,096-update configurations, all completed. Every checkpoint, summary and the primary index is checked by byte count and SHA-256 at G and F, as are the summaries' nested training-log, probe and validation artifacts. Their bytes must be unchanged. This verifies the existence of the bound files in the actual Git ancestor; it does not rely on a local receipt merely asserting their existence.

G must contain no final-stage files or directories, except the deliberately pre-final `study/final_inventory.json`, and no gate receipt. The helper checks that training had completed, the source/plan/recipe identities agree, and the source ZIP and plan/recipe copies remain identical. It checks the access receipt's link to the gate receipt and the final-data descriptor's link to the consumed access. Recorded timestamps must order training, inventory creation, intermediate copy, gate receipt, final start, consumed access, completion and final archive. Git author/committer dates are preserved as metadata, not used as independent proof of publication time.

An optional `--job-log PATH` accepts the complete UTF-8 **text** log for the relevant Actions worker step or job, not a ZIP. The parser recognizes the frozen worker's actual `evidence_archived` and `resource_heartbeat` JSON records, allowing a retained text prefix such as an Actions timestamp. It requires exactly one matching archive event for G, verifies its file count/snapshot kind and recorded UTC between copy and receipt, and checks its line order before all final-stage heartbeats. It also compares that archive event's recorded UTC with the final-start timestamp in `final_status.json`.

The frozen worker does **not** emit a stdout event announcing final-stage start. The audit therefore does not invent such an event or describe the first heartbeat as the exact start. A supplied log lacking the matching event or final heartbeat produces an explicit issue; no log leaves log corroboration explicitly absent. Prefix timestamps are retained without assuming who supplied their clock. Root should preserve the log's independently obtained provider provenance separately; this helper records the text file's hash and selected original events.

Every encountered check failure is retained, and independent sections continue where possible. Structural failures record the exception and the dependent scope that could not complete. A nonzero exit and exclusive JSON receipt preserve failure; no input is repaired and no previous receipt is overwritten. The report includes the helper hash, Git-object input hashes, check outcomes, ancestry, inventory, timestamps and optional log evidence. Admission requires at least 8 GiB available RAM; no numerical libraries or numerical threads are started. Only syntax compilation is performed when authoring this helper. Root owns its first execution against the completed, recovered raw archive and must retain that first success or failure.

The strongest supported conclusion is that the bound training inventory existed in the specified recovered Git ancestor and that the archived sequence is consistent with the frozen worker confirming its push before final access. Git ancestry alone does not prove the wall-clock time of a remote push. The worker's successful push and `ls-remote` check, retained Actions events and later remote recovery supply operational corroboration under shared custody. They do not establish external blinding, external replication, or absence of unrecorded copies or access elsewhere. The separate full-source/archive audit and independent scientific recount retain their own responsibilities; this helper does not replace them.
